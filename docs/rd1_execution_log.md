# RD1 로컬 구현과 실측 실행 기록

기준 명세: `연구설계_최종의사결정.md` RD-1.0. 시작일: 2026-11-09.

## 승인 범위와 실행 안전장치

사용자가 원자료 기반 사례 생성, 그래프 생성, 고전 검증과 논문 형식 DOCX 작성을 승인했다. QPU 실행은 금지다. 이번 실행 경로는 QPU 모듈, 계정 인증, 기존 노트북을 가져오거나 실행하지 않는다. 기존 결과와 원본은 보존하고 새 `outputs/rd1` 경로에 기록한다.

## 구현 분담과 순서

1. 자료: 전체 원본 해시, 중복·결측 감사, 일자 캐시, 과거 OD, 전체 창 등록과 날짜 분할.
2. 후보: 총 보행·시간·관측 적격성, 전체 대안, 고정 S/L/J, 체크포인트 제약과 사건 검증.
3. 그래프와 풀이: 정확성 판정·CNF 변환, 단위 통일된 고전 기준선, 실제 풀이에 근거한 난도 판정.
4. 통합: 고정 실행군, 재실행·중단 기록, 필터 해제 민감도, 운영 기준선과 결과 요약.
5. 검증과 보고서: 의미 있는 경계조건 테스트, 실제 입력 실행, 독립 검토, 인용과 범위를 명시한 DOCX 및 페이지 렌더 검수.

## 구현상 판단 기록

- `codex/rd1-local-research` 브랜치에서 수정한다. 기존 수정·미추적 문서 및 결과를 보존한다. 사용자 지정 데이터 경로를 유지하며 원본 대용량 자료는 복제하지 않는다.
- 새 모듈은 기존 결과 재현용 코드를 남기고 RD-1.0 실행 진입점과 연결한다. 기존 37개 결과는 새 설계의 실행 결과에 합치지 않는다.
- 전체 적격창 등록과 실제 생성·풀이 완료 범위는 별도 분모로 기록한다. 연간 모든 창을 풀이했다고 자동으로 주장하지 않는다.
- 문서의 실행하지 않은 QPU 부분은 현재 승인 0원 및 미실행 상태로 유지한다.
- 전체 연간 창 등록 후, 이번 로컬 실행군은 월별 원래 요청 수의 2의 거듭제곱 규모층에서 최대 3개씩 고정 시드로 추출하고 월 최대 이용 창 2개 및 명세의 피크 창을 합친다. 이는 새 운영 모형이나 새 고난도 기준이 아니라 이번 탐색 실행의 범위다. 실제 생성·풀이 범위 밖의 창은 미실행으로 남기며, RD1의 잔여 그래프 규모별 일반군은 실제 그래프 측정 후 별도로 추출한다. 실행 범위를 결과 보고서에 명시한다.

## 진행 상황

- 자료·후보·고전 검증의 독립 구현을 시작했다.
- 실행군 순서 독립성·제외창 보존·20개 기준·인코딩 실패와 미해결 구분 테스트: 구현 전 ImportError 확인 후 3개 통과.
- 추가 반례: 잔여 규모 미측정을 축약 0으로 표시하는 오류를 실패 테스트로 확인하고 `unavailable`로 분리했다. 캠페인 테스트 4개 통과.
- `.venv-classical` 독립 환경에서 기존·신규 로컬 모형 테스트 83개 통과(10.80초). QPU 테스트·모듈은 실행하지 않았다. 이후 추가 변경은 별도 검증한다.
- 독립 검토의 일별 자료 반환형 오류와 자정 이후 완료 여행의 과거 OD 누출을 실패 테스트로 확인해 수정했다. OD 캐시는 `completed_v2`로 구별한다. 80개 작은 혼합부호 모형의 모든 배정에서 CNF·lift/decode·최적값 항등식도 독립 검증했다.
- 실제 개발 파일럿에서 편익 필터 해제 56,939후보의 누적 사건 계수 저장량이 2.18GB가 되는 문제를 확인해 해당 파일럿 프로세스만 중단했다. 사건 검증을 동치인 희소 시간순 재생으로 바꾸어 61.74MB로 줄였다. 주 체크포인트 제약·후보·목적은 유지했다. 중단 파일럿은 주 결과에 합치지 않는다.
- 탐욕법은 매 후보마다 전체 모형을 다시 검사하는 대신, 이미 실행 가능한 선택에서 바뀌는 희소 행의 활동량만 검사한다. 혼합부호 모형 100개와 기존 실제 소형 사례에서 이전 방식과 같은 선택을 확인했다.
- 수정 후 로컬 전체 검사 99개 통과(7.05초), QPU 관련 테스트 제외. 검증된 새 파일럿을 별도 폴더에 실행한다.
- 추가 개발 설정 고정: 같은 1월 3일 개발 입력에서 CP-SAT의 단일 스레드 기본 선형화가 60초에 증명을 못해, 선형화 수준 2를 1회 확인했다. 전처리 포함 0.214초에 원그래프 최적값 3,887(추천 18)을 증명했다. 이후 모든 평가 입력에 수준 2를 고정하며 결과에 실제 설정을 기록한다. 근거는 개발 검증 및 CP-SAT의 선형 완화 기능이며, 특정 논문이 이 수치를 처방한 것은 아니다. 평가 입력 결과로 재조정하지 않는다.

## 정확 쌍둥이 축약과 제한시간 검사 보완

- 평가 날짜를 열람하기 전 개발 사례 2025-01-03 08시 강서구에서 원모형은 추천 18개를 즉시 증명했지만, 쌍둥이 정점을 펼친 HiGHS 그래프 풀이가 설정 60초를 넘어 131.33초에 반환되는 현상을 확인했다. 해당 미완료 실행은 `outputs/rd1_unreduced_development_diagnostic`에 보존하며 고정 예산의 주 결과에 합치지 않는다.
- 두 그래프 정확법에 동일한 **false-twin 정확 축약**을 적용한다. 열린 이웃집합이 같은 정점들은 서로 비인접하고 바깥 이웃이 동일하다. 독립집합에서 그중 하나를 선택했다면 나머지도 전부 추가할 수 있으므로 최대해는 각 묶음을 전부 선택하거나 전혀 선택하지 않는다. 대표 정점의 정수 목적계수를 묶음 크기로 두면 축약 문제의 최적값은 원래 비가중 MIS의 크기와 같다. 이것은 자체 수학적 정당화를 갖는 고전 전처리 구현이며 외부 문헌의 수치 처방으로 제시하지 않는다.
- 실제 연구 입력과 저장된 `exact_graph.json`은 비가중 원그래프 그대로다. 내부 고전 풀이에서만 대표 정점의 개수 계수를 사용하며, 해는 원래 정점 ID로 모두 복원해 독립성과 크기를 검사한다. QPU에 가중치를 전달하거나 원래 엣지를 바꾸지 않는다.
- 열린 이웃집합 생성·묶음 구성 시간을 60초에서 차감하여 두 정확 풀이기에 남은 시간을 전달한다. 전처리 전후 노드·엣지 수, 전처리·모델 생성·실제 풀이·복원 검증 시간을 별도로 저장한다. `budget_elapsed_seconds = preprocessing_seconds + solver_seconds`가 설정 시간보다 0.5초 넘으면 `budget_overrun=True`로 기록한다. 이는 실제 제한시간을 숨기지 않기 위한 계측 규약이다.
- 예산 초과 실행의 유효 해·상계·최적성 증거는 진단용 원시 실행 기록에 남기되 고정 예산 포트폴리오의 해/상계 및 정상 반복·고난도 판정에서 제외한다. 다른 정상 실행이 증명한 최적성은 그대로 인정한다.
- 5정점 이하 모든 단순 그래프 1,100개의 원래 MIS와 축약 가중 MIS 최적값을 전수 비교해 일치를 확인했다. 별도로 원래 ID 복원, 가중 상계의 원래 개수 단위, 초과 예산 결과의 포트폴리오 제외를 검사했다.
- 같은 개발 사례를 `outputs/rd1_twin_development_check`에 60초 × 1회로 재실행했다. 8,002노드·235,479엣지가 197대표·231엣지로 축약되었다. 원모형 HiGHS는 0.0010초, 그래프 HiGHS는 전처리 0.1623초와 풀이 0.0232초에 추천 18개 최적을 증명했다. CP-SAT는 전처리 0.1631초와 풀이 59.8390초에 추천 18개를 찾았으나 자체 최적성 증명은 완료하지 못했다. 포트폴리오 상하계는 18로 일치하며 예산 초과는 0회다. 이 1회 개발 검사는 5회 주 실험을 대신하지 않는다.

## 2026-11-09 완료 실행과 최종 검산

- 연간 219,000개 창을 등록하고 적격 216,540개 중 사전에 고정한 440개 창(251일)을 실행했다. 주 조건과 필터 해제는 각각 440개, 월별 고정 창의 추가 민감도는 120개다. 창 내부의 요청·이웃 수는 자르지 않았다. 등록 모집단을 전부 풀이한 결과는 아니다.
- 주 실행 880개와 민감도 120개 모두 정상 종료했고 운영 모형의 최적값을 증명했다. 주 실행은 7,654.50초, 민감도는 2,590.50초였다. 이 시간은 각 캠페인의 경과시간이며 자료 준비·개발 진단·보고서 작성 시간은 포함하지 않는다.
- 주 실행의 사전 기준상 상대적 고난도와 미해결은 각각 0개다. 민감도 변형당 12개는 규모 구간당 20개 요건을 충족하지 못하므로 상대 난도 분류는 표본 부족이다. 정확화 실패와 후보 생성 비용을 운영 문제의 고전 난도로 세지 않았다.
- 주 조건의 비어 있지 않은 168개 중 73개는 검산된 해가 요청 상한에 도달했고, 95개는 재고 제약이 최적 추천 수를 제한했다. 필터 해제의 비어 있지 않은 436개는 각각 290개와 146개다.
- 주 조건 64/440개에서 집합 BENEFIT이 음수였다. 개발·평가의 실제 반례를 독립 검산했다. 모든 후보의 개별 편익이 양수여도 개선의 중복과 신규 부족으로 집합 지표가 악화될 수 있다. 근거는 `outputs/rd1_result_audit/final_benefit_audit.json`이다.
- 생성 실패의 0개를 실제 후보 0개로 통계에 넣지 않도록 유효 생성 상태와 제외 분모를 분리했다. 정상 무후보 상태인 `no_travel_eligible_candidate`도 포함하며 사건 검증 역시 같은 상태 집합을 사용한다. 개발·평가 통계와 고정 창의 대응 민감도 통계를 별도로 저장했다.
- Windows CRLF를 LF 정규형으로 정리한 JSON은 7,816개다. 수치·선택·논리 그래프는 바꾸지 않았으며 연결 파일 해시 2,379개를 실제 바이트와 대조했다. 전후 해시는 `outputs/rd1_postanalysis/artifact_integrity.json`에 보존했다.
- 최종 로컬·독립 테스트 **123개 통과(11.44초)**. QPU 테스트는 명시적으로 제외했다. 분석 코드 13개는 시작 시 해시와 같으며 주·민감도 실행도 같은 코드를 사용했다. 실제 버전·명령·검증 결과는 `outputs/rd1_verification.json`, 하드웨어 정보는 `outputs/rd1_environment.json`에 저장했다.
- QPU·인증·계정 정보·노트북은 실행하지 않았다. 최종 DOCX는 완료된 산출물만 읽어 작성하고 별도 페이지 검수를 수행한다.
