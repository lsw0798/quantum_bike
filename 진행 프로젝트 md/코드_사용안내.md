# RD1 실측 연구 코드 사용 안내

`연구설계_최종의사결정.md`의 자료·후보·체크포인트 모형을 실행하는 진입점은 **run_rd1_research.py**입니다. 원자료는 `origin_data`에서 읽고, 기존 37개 탐색 결과와 분리해 새 출력 폴더에 저장합니다. 이 실행기는 QPU·계정·노트북을 실행하지 않습니다.

## 코드 읽는 순서

| 순서 | 파일 | 역할 |
|---|---|---|
| 1 | bike_research/rd1_data.py | 원본 해시, 중복 정리, 날짜별 캐시, 과거 OD, 전체 창 목록과 날짜 분할 |
| 2 | bike_research/campaign.py | 풀이 결과를 보기 전 실행군 고정, 측정 후 난도·일반군 분류 |
| 3 | bike_research/rd1_cases.py | 실제 이용 한 행의 모든 적격 출발·반납 대체 조합 생성 |
| 4 | bike_research/benefit.py | 재고 변화 δ, 고정 기준 L, 부족량 J, 편익, 사건 경로 검증 |
| 5 | bike_research/graph.py | 같은 요청·확인된 자원 충돌, 후보 그래프와 완화 여부 |
| 6 | bike_research/encoding.py | 일반 재고 제약을 보존하는 보조 정점 MIS, lift와 decode |
| 7 | bike_research/benchmark.py | 원모형 HiGHS, 정확 그래프 HiGHS·CP-SAT, 반복 실행과 상하계 |
| 8 | run_rd1_research.py | 위 단계를 연결하고 실패·중단·해시·실행 결과 보존 |
| 9 | run_rd1_sensitivity.py | 월별 고정 창에서 이동 조건을 하나씩 바꿔 재검증 |
| 10 | analyze_rd1_results.py | 파일 무결성, 날짜별 통계, 무작위 기준선과 사건 민감도 |
| 11 | analyze_rd1_structure.py | 요청 상한 도달과 재고 제약의 영향을 독립 검산 |
| 12 | build_rd1_report.py | 완료된 결과만 읽어 논문 형식의 DOCX 작성 |

`data_process.py`와 기존 `cases.py::create_case`는 이전 탐색 결과 재현용으로 유지했습니다. RD1 실행과 혼합하지 마세요. 원모형의 추천 수와 보조 그래프의 독립집합 크기는 서로 다른 값입니다.

## 로컬 실행

프로젝트 폴더의 PowerShell에서 실행합니다. 분석 환경은 QPU 환경과 분리한 `.venv-classical`입니다.

```powershell
# 원본 정리와 연간 창 목록만 준비
.\.venv-classical\Scripts\python.exe -m bike_research.rd1_data --root origin_data --cache outputs/rd1_data_cache

# 고정된 월별·요청 규모별 실행군과 편익 필터 해제 조건을 함께 실행
.\.venv-classical\Scripts\python.exe run_rd1_research.py --output outputs/rd1_main

# 같은 코드·설정·입력의 완료 결과를 보존하고 중단 지점부터 재개
.\.venv-classical\Scripts\python.exe run_rd1_research.py --output outputs/rd1_main --resume

# 별도 출력 폴더에서 연간 모든 적격창을 실행할 때만 사용
.\.venv-classical\Scripts\python.exe run_rd1_research.py --all-windows --output outputs/rd1_all_windows
```

전체 창 등록은 전수 작업이지만 기본 실행군은 표본입니다. 기본 실행군은 월별 원래 요청 수의 2의 거듭제곱 규모층마다 최대 3개, 월별 최대 이용 창 2개, 명세의 피크 창을 합칩니다. 각 창 안에서는 요청 수나 이웃 수를 자르지 않습니다. 실제 선택 목록은 풀이 전에 `execution_cohort.csv`로 고정합니다. 표본 밖의 창을 쉬운 사례나 고난도 사례로 판정하지 않습니다.

## 결과 파일

| 파일 | 확인할 내용 |
|---|---|
| manifest.json | 입력·코드·설정 해시, 전체 등록 수와 실제 실행 수, 예산 |
| window_registry.csv | 전체 창과 개발·평가 분할, 자료 제외 사유 |
| execution_cohort.csv | 이번 실행에 고정한 날짜·시간·자치구와 선정 이유 |
| summary.csv / summary.json | 사례별 후보·그래프 규모, 고전 최적성, 편익과 사건 검사 |
| cases/각 사례/case.json | 실제 요청 출처, 대체 후보, 관측점 제약·희소 사건 기록, B/L/δ |
| cases/각 사례/graph.json | 후보가 정점인 그래프와 정확성/완화 표지 |
| cases/각 사례/exact_graph.json | 생성에 성공한 정확 MIS. 보조 정점이 포함될 수 있음 |
| cases/각 사례/build_summary.json | 변환 성공·한도 초과·원모형 검사 |
| cases/각 사례/classical_runs.json | 알고리즘별 60초 한도·5개 시드 실행 기록 |
| cases/각 사례/operational_evaluation.json | 원래 이동·두 탐욕법·최선 고전 해의 동일한 운영 지표 |
| completion.json | 실제 완료 수와 측정된 고난도·미해결 수 |

`encoding_limit_exceeded`는 고전 풀이의 시간초과가 아닙니다. `snapshot_semantics_assumed`는 시간별 수량을 정시 직전 순간값으로 해석한 조건부 결과임을 뜻합니다. 실제 반납 용량과 이용자 수락률은 자료에서 확인하지 못했으므로 효과를 만들어 넣지 않습니다.

사건 검증은 `event_validation`의 희소 시간순 기록을 재생합니다. `event_constraints`의 빈 목록은 사건 제약이 없다는 뜻이 아닙니다. 사건 유효성은 반드시 `benefit.evaluate_selection`으로 확인하세요.

그래프와 사례의 연결 해시는 UTF-8 JSON의 LF 줄바꿈 정규형 기준입니다. 후속 `analyze_rd1_results.py`가 완료 파일의 Windows CRLF를 LF로 정리하고 실제 파일 바이트 해시까지 대조합니다. 이 처리는 JSON 값과 계산 결과를 바꾸지 않으며 `artifact_integrity.json`에 전후 해시를 남깁니다.

```powershell
# 월별 고정 창에서 거리·속도·지연·OD 관측 기준을 한 번씩 변경
.\.venv-classical\Scripts\python.exe run_rd1_sensitivity.py

# 날짜 블록 통계, 동일 실제 그래프의 난수 기준선, 사건 순서·지연 부검증
.\.venv-classical\Scripts\python.exe analyze_rd1_results.py

# 위 후처리로 파일 해시를 확인한 다음, 쉬움 인증과 재고 제한 이유를 정리
.\.venv-classical\Scripts\python.exe analyze_rd1_structure.py --input outputs/rd1_main
```

`statistics_by_split.json`은 개발·평가 기간을 분리하고, `sensitivity_statistics.json`은 월별로 고정한 창에서 변경 조건과 주 조건을 비교합니다. 생성이 중단된 사례의 후보 수는 실제 0개로 취급하지 않습니다. 각 비교에 포함·제외된 사례 수를 함께 저장합니다.

로컬 분석 테스트는 다음 명령으로 실행합니다. QPU 관련 테스트는 제외합니다.

```powershell
.\.venv-classical\Scripts\python.exe -m pytest tests --ignore=tests/test_qpu.py -q
```

`build_rd1_report.py`는 완료된 결과 파일만 읽어 `연구결과_보고서.docx`를 작성합니다. 문서 작성에는 `python-docx`가 있는 별도 문서 환경을 사용하며, 분석이나 QPU를 다시 실행하지 않습니다.
