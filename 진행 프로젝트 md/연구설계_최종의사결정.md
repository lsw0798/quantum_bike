# 실측 따릉이 자료 기반 비가중 MIS·QPU 연구설계 최종 의사결정

작성·결정일: **2026-11-09 (Asia/Seoul)** · 설계 버전: **RD-1.0**

**이 문서는 이번 연구에서 채택할 방법을 확정한다. 구현 완료·실험 성공을 뜻하지 않는다.** 기존 `레퍼런스.md`의 D01–D70을 모두 검토하고 추가 결정 D71–D78을 등록했다. 기존 고난도 선정 규약의 60초×5회·시간순 분할을 유지하면서, 비교 대상은 **본 문서의 최종 후보·제약·정확 MIS**로 명확히 한다. 충돌하는 이전 초안보다 이 문서의 설계가 우선하며, 실제 코드와 JSON 설정의 변경은 §9의 후속 구현 목록에 남긴다.

## 1. 채택한 연구와 주장 범위

실제 완료 여행을 요청으로 재구성한 **회고적 조건부 추천 실험**을 수행한다. 실제 대여소로 이동 대안을 만들고, **개별적으로 관측 재고 부족 지표를 줄이는 후보들 중 선언된 제약을 만족하는 최대 개수**를 비가중 MIS로 선택한다. 고전 방법과 QPU는 같은 논리 문제를 풀며, 선택 개수와 집합 전체의 수급 기여를 각각 평가한다.

| 핵심 결정 | 채택 내용 |
|---|---|
| 자료 | 서울 실제 대여·반납, 대여소, 시간별 대여가능 수량. 실패 요청·가상 재고·가상 운영자 이동을 추가하지 않음 |
| 주 운영 모형 | 시간별 관측값을 해당 정시 사건 직전의 재고로 해석하는 **조건부 체크포인트 모형**. 모든 관측점의 하한을 검사 |
| 사건 검증 | 모든 선택 해에 사건별 재고 검증을 추가하고 통과율·위반량·통과 하위군을 보고. 체크포인트 통과를 사건 전체 실행 가능성으로 부르지 않음 |
| 반납 용량 | 실제 운영 상한이 확인된 경우에만 제약·평가를 활성화. 현재 자료로 반납 실패·포화·교착 개선을 수치화하지 않음 |
| 목적 | `max Σ x_v`: 적격 추천 개수. 수급 지표는 후보 자격과 결과 평가에 사용하며 MIS 가중치로 사용하지 않음 |
| 그래프 | 전체 **선언 모형**과 동치인 후보 그래프 또는 정확한 보조 노드 인코딩을 본 실험에 사용. 쌍별 완화 그래프는 진단용 |
| 양자 경로 | QoolQit/Pasqal의 검증된 직접 배치 경로. 장치 변환 실패·크기 초과도 결과에 포함 |
| 효과 해석 | 선택된 추천을 모두 실행한다는 조건하의 재고 지표 변화. 실제 수락률·실제 서비스 개선·온라인 운영 가능성을 입증한 결과로 해석하지 않음 |

주 모형을 체크포인트 방식으로 정한 이유는 수량 자료가 시간별이기 때문이다. 사건 재구성은 미관측 공급과 시각 의미에 민감하므로 필수 별도 검증으로 둔다. 공식 제공 페이지는 **1시간 단위**를 명시하지만 순간값인지 구간 요약인지까지 이번 확인에서 해소되지 않았다. 그동안 순간값 해석을 **가정으로 표시한 분석을 계속하며 현실 재고 복원 인증은 하지 않는다**. 평균값 등 다른 정의가 확인되면 해당 결과를 순간재고 연구의 증거에서 제외하고 그 자료 정의에 맞춘 새 설계 버전을 만든다. [S03]

## 3. 수치·수식을 포함한 공통 실험 규약

아래의 구체 숫자는 **본 연구에서 채택한 규약**이다. 문헌이 해당 서울 최적값을 제시했다고 인용하지 않는다. 문헌은 표의 원리·비교 관점을 뒷받침하고, 신규 공식·수치에 직접 근거가 없는 경우 N으로 표시한다.

### 3.1 모집단·시간·표본

- 시각은 Asia/Seoul, 정시 시작 `t0`, 요청창 `[t0,t0+60분)`, 간격 60분, 출발 대여소의 자치구별로 구성한다. 원래 이용시간은 `0 < d ≤ 120분`. 이 범위 밖 실제 여행도 관련 배경 사건으로 유지한다.
- 해당 창의 적격 요청 전체를 등록한다. 실험 규모를 맞추기 위한 앞 n개 절단은 주 분석에 사용하지 않는다. 연간 전체 적격창 목록·제외 사유를 먼저 만든다. 로컬 후보/제약 생성은 창당 **600초·메모리 4GiB**, 정확 그래프 생성은 **60초** 상한으로 중단 사유를 남긴다. 중단 사례를 완료 모집단에서 숨기지 않는다.
- 대체 여행의 마지막 반납은 `t0+4시간` 이내로 제한한다. 관측 재고는 `t0,…,t0+4시간`, 편익 평가는 `t0+1,…,+4시간`의 네 시점. 다음 한 시간의 이동까지 쓰므로 `t0+5시간`까지 문맥을 확보한다. 자정·월 경계와 창 전에 출발한 관련 여행도 읽는다.
- 기존 두 날짜는 개발 자료로 고정한다. 그 외 적격 날짜의 앞 `floor(0.7n)`일을 잠정 개발로 두고, **잠정 경계와 이미 확인한 마지막 날짜 중 더 늦은 날짜**를 개발 종료일로 정한다. 이후 날짜만 평가에 사용한다. 개발 창의 +5시간 문맥이 첫 평가일 00:00에 닿으면 그 창을 개발에서 제외한다. 실제 분할 비율과 경계 제외 수를 보고한다. 한 날짜의 모든 지역·변형은 같은 쪽에 둔다. 평가일 관측 이동은 회고적 입력으로 사용하되 결과로 매개변수를 조정하지 않는다. 평가일 부족 시 개발 결과로만 보고한다.
- 일반군은 규모 구간별 최대 3개를 고정 시드 20261109로 추출한다. 잔여 크기 0은 별도 `certified_zero` 구간이며, 인증으로 축약을 생략한 경우와 실제 삭제로 0이 된 경우를 구별한다. 운영 위험군은 **J(0)>0**, 사건 기준선 실패는 별도 태그다. 피크군은 기존의 **월별 이용건수 최대 월 → 상위 2일 → 그날 출발량 상위 2시간 → 해당 시간 출발량 최대 자치구**로 고정하며 동률은 날짜·시간·지역명 순으로 처리한다. 태그 중복과 각 군 분모를 보존하고 고난도 표본을 서울 평균으로 일반화하지 않는다.
- 대여소 메타데이터는 날짜 차이 **183일 이내의 가장 가까운 보유 스냅샷**, 동률이면 과거 것을 사용한다. 미래 스냅샷이면 `retrospective_metadata_proxy`를 표시한다. 실제 해당 시각의 활성 여부는 이용·재고 기록으로 확인 가능한 범위만 사용한다. ID·좌표가 없거나 범위 밖이면 제외하며 새 대여소를 만들어 채우지 않는다.
- 동일 물리 여행 키(자전거 ID·출발/반납 시각·출발/반납 대여소)의 중복은 한 번만 사용하고 출처 목록을 남긴다. 재고의 동일 대여소·시각 중복은 값이 같으면 합치고 다르면 해당 관측을 결측 처리한다. 음수·비유한·정수가 아닌 재고를 임의 보정하지 않는다. 유효한 한쪽 사건만 알려진 여행은 그 사건을 배경에 유지하고 미확인 반대 사건 수를 보고한다. 이 경우 관측 로그의 완전성은 주장하지 않는다.

### 3.2 이동 후보와 수락

- 원래 대여소 위치를 보행 출발지·최종 목적지의 대리값으로 쓴다. 변경 출발·반납 대여소의 조합을 모두 열거하되 원래와 동일한 조합은 추천 후보에서 제외한다.
- **양 끝 보행 거리 합 500m 이하**, 각 끝점 반경도 500m 이내. 거리는 대권거리로 계산하고 실제 도로 보행거리라고 부르지 않는다. 가장 가까운 k개 제한은 없으며, 자료 및 실행 예산으로 중단하면 `generation_limit`으로 보고한다.
- 변경 OD의 승차시간은 **해당 날짜 이전 28일**, 같은 방향 대여소 쌍의 유효 여행 중 `0<이용시간≤120분`의 중앙값(최소 10건). 부족하면 이전 **90일**까지 확장해 같은 조건 적용. 그래도 부족하면 `insufficient_travel_evidence`로 제외한다. 이전 평가 날짜의 기록은 고정된 규칙의 순차 추정에 사용할 수 있지만, 해당 날짜와 미래 여행은 사용하지 않는다. 기존 직선거리 차이/4m·s⁻¹ 모델은 민감도 분석에만 유지한다.
- 주 보행 속도 **1.2m/s**. `새 대여 = 원래 대여 + 출발 보행시간`, `새 반납 = 새 대여 + 추정 승차시간`. 최종 목적지 도착은 도착 보행을 더한다. 원래 반납보다 늦어지는 총시간은 **15분 이하**이며, 원래 반납시각을 변경 경로에 그대로 복사하지 않는다.
- 주 분석은 선택 추천의 **조건부 100% 실행**을 가정한다. 수락 확률·보상금·가상 이용자를 표본 생성하지 않는다. 전부 수락은 실제 효과의 수학적 상한도 아니다. 공급 의존성 때문에 부분 수락에서 실행 가능성이 달라질 수 있다.
- 민감도는 한 번에 한 조건씩 변경한다: **총 보행 한도 R와 끝점 검색 반경 R을 함께** 200/750/1000m로 변경, 속도 1.0/1.4m/s, 지연 5/30분, 과거 OD 최소 표본 5/20건, 기존 이동시간 근사, 편익 필터 해제. 시각은 초 단위로 올림하고 4시간 종료 한도는 모든 변형에 유지한다. 각 변형은 새 입력·새 난도이며 동일 사례 ID를 덮어쓰지 않는다. 거리 수준만 R09의 설문 수준을 참고했으며 선호 상한의 실증으로 사용하지 않는다. [R09]

### 3.3 후보의 수급 기여와 비가중 목적

`S`는 해당 창의 다섯 재고 관측점이 모두 있는 실제 대여소 집합이다. 비교 알고리즘·민감도 변형에 같은 S를 사용하고, 원래/대체 끝점이 S 밖인 요청·후보는 자료 부족으로 제외한다. S와 관측 이동 집합은 편익 필터 적용 전에 고정한다.

시점 h부터 다음 한 시간 동안 실제 완료 로그의 누적 대여/반납을 `D_s,h(u), A_s,h(u)`라 하자. 같은 시각이면 대여 후 반납의 보수적 순서를 사용한다.

`L_s,h = max(0, max_{0≤u<1시간} [D_s,h(u) − A_s,h(u)])`

L은 **고정된 관측 사건 순서를 외부 추가 공급 없이 지원하는 초기 보유량**이다. 잠재 수요나 최적 목표 재고로 부르지 않는다. 순유출 총합만 쓰면 중간의 재고 부족을 놓치므로 누적 최댓값을 사용한다. [R06], 공개본 §3.

후보 v가 만드는 시각 h 직전의 재고 변화는 다음 네 사건의 차이다. 지시함수는 해당 대여소에서 **사건 시각 < h**일 때 1이다.

`δ_s,v(h) = +1[원래 대여] −1[원래 반납] −1[대체 대여] +1[대체 반납]`

`I_s,h(x) = B_s,h + Σ_v δ_s,v(h) x_v`

`J(x) = Σ_{s∈S, h=t0+1h,…,+4h} max(0, L_s,h − I_s,h(x))`

`BENEFIT(x) = J(0) − J(x)`

- B는 실제 시간별 수량이며 보간하지 않는다. J의 단위는 **관측점별 자전거 부족량 합**이다. 실제 실패 건수·서비스율·인과적 효과가 아니다. 이미 완료된 여행을 사용하므로 양의 부족량에는 미관측 운영자 공급·시각 불확실성도 반영될 수 있다.
- `B+δ`는 추천 외의 배경 이용과 미관측 운영자 활동이 추천에 반응하여 바뀌지 않는다는 고정 환경 가정이다. 실제 운영자의 대응 정책까지 관측·복원했다는 뜻이 아니다. 해당 가정의 현장 타당성은 현재 자료로 검증되지 않았다.
- 주 후보는 `b_v = BENEFIT(e_v) > 0`인 이동 적격 후보다. b는 정수 재고 지표 기준으로 계산한다. 계산상 허용 오차 1e-7은 시간·좌표 연산 검증에만 쓰고 자전거 수를 반올림하여 만들지 않는다.
- 목적은 `max Σ_v x_v`, 요청별 `Σ_{v∈V_r}x_v ≤ 1`, 선언된 재고·자원 제약을 함께 적용한다. **b_v를 가중치로 쓰지 않는다.** 원래 이동은 미선택 시 유지하고 선택 시 사건 차이로 대체한다.
- 개별 b_v>0이어도 집합 BENEFIT은 0 또는 음수일 수 있다. 최종 모든 해에서 J를 다시 계산하고 악화율을 보고한다. 단독 편익 필터는 도움이 되는 0·음수 후보를 제거할 수 있으므로 **필터 해제 분석을 필수 수행**한다. 단독 재고 불가능만으로 후보를 추가 삭제하지 않는다.
- L은 원래 관측 이동을 고정한 평가 기준이다. 선택된 경로로 미래 수요 전체를 다시 생성하는 서비스 시뮬레이터가 아니다. 이 전체 J·필터 공식의 직접 선행 근거는 **미확인(N)**이다. 재고 경로와 기준 여행 대비 평가 관점만 R04/R06에서 전용한다.
- J(0)=0이면 양의 개별 편익 후보는 생길 수 없다. 이런 창과 후보가 0개인 창은 `no_beneficial_candidate`로 보존하고 QPU 과제에서 제외한다. 목표 재고를 임의로 올려 후보를 만들지 않는다.

### 3.4 운영 제약과 확인되지 않은 사실의 처리

주 분석은 모든 체크포인트의 `I_s,h(x) ≥ 0` 및 요청 배타성이다. 현재 실제 수용 상한 C는 미확인이므로 상한을 임의 대입하지 않는다. C가 검증된 지역·시점의 확장 모형에는 `I_s,h(x) ≤ C_s,h`를 추가하고 별도 버전으로 재생성한다.

모든 해에 대해 `B_s,t0 + 실제 배경 사건의 누적 + 후보 사건 차이`로 사건별 재고도 계산한다. 정시 관측은 그 시각의 사건 **직전**으로 통일한다. 같은 시각의 모든 출발을 먼저 처리하고 반납을 처리한다. 반납 우선 순서는 민감도 분석으로만 둔다. 처리 지연은 주 모형 0초, 추가 민감도 60초로 정하며 실제 처리시간 측정값으로 부르지 않는다.

| 관측·검증 상황 | 확정된 처리 |
|---|---|
| 순간값 의미 미확인 | 모든 결과에 `snapshot_semantics_assumed` 표시. 조건부 분석을 수행하고 현실 복원·실행 가능 인증 표현 제한 |
| 원래 사건 경로가 음수 | 사건 모형 기준선 실패로 기록. 체크포인트 분석은 별도 유지; 엄격 사건 하위군에서 제외 |
| 사건 재구성과 다음 관측값 불일치 | 잔차 그대로 저장. 가상 운영자 이동으로 메우지 않음 |
| 엄격 사건 하위군 | 기준선과 선택 해의 모든 사건 제약 통과, 모든 관측점 잔차 **정확히 0**인 사례. 순서·시각 가정에 조건부이며 실제 실행 인증은 아님 |
| 실제 반납 상한 미확인 | 반납 불가·포화·교착 개선 지표는 NA. 공개 거치대 수/관측 최댓값을 C로 사용하지 않음 |
| 동일 시각 대여·반납 | 사건 순서 민감도로 평가. 대기·락·점유 자료 없이 교착이 관측됐다고 주장하지 않음 |
| 개별 자전거 위치·개인 ID 불확실 | 집계 수량과 동일 요청 배타성만 사용. 추정 개인 식별·실체 없는 자전거 슬롯을 실제 자원으로 표시하지 않음 |
| 예측/관측 상태가 선호와 다름 | 보행 속도·거리·지연은 모형 가정으로 보존. 실측 수락으로 바꾸지 않음 |

### 3.5 정확 MIS와 QPU 입력

1. 원래 모형에서 검증된 실행 가능 해를 확보한다. 체크포인트 주 모형은 x=0을 독립 검사하여 증인으로 사용한다. 일반 확장 모형이 불가능하면 `infeasible`, 확인 못하면 `feasibility_unknown`으로 종료한다.
2. 같은 요청의 대안은 clique. 실제 확인된 독점 자원의 동시간 사용만 자원 충돌로 추가한다. 다른 후보의 공급으로 구제될 수 있는 쌍을 영구 금지하지 않는다. 고차 수량·양의 의존성이 남으면 후보 그래프를 완화로 표시한다.
3. 선언 제약과 후보 그래프의 동치가 검증되면 그 그래프를 직접 사용한다. 그렇지 않으면 기존 CNF→쌍둥이 정점 인코딩을 사용한다. 후보 수 N, 절 수 m, `W=N+1`일 때 **실행 가능한 원모형에 한해** `α(G)=Wm+OPT`라는 로컬 구성의 증명을 적용한다. 이는 일반적으로 효율적인 인코딩이라는 주장이 아니다.
4. 인코딩 한도는 지지 크기 16·절 5,000·노드 12,000·엣지 500,000·벽시계 60초로 통일한다. 초과 시 중단하고 제약·후보를 버리지 않는다. 현재 코드의 함수 기본값과 호출값이 다르므로 설정 일원화가 필요하다.
5. 후보 그래프/보조 그래프의 입력 해시와 복원표를 고정한다. 일반 고전 MIS 외에 **원래 운영 MILP 해를 정확 그래프로 옮기는 기준선**도 포함한다. 인코딩 부풀림으로 생긴 지연을 운영 자체 난도로 보고하지 않는다.
6. 주 양자 실험은 검증된 직접 배치만 사용한다. 수치 임베딩 오차가 작다는 사실만으로 정확성을 인정하지 않는다. 실패는 `uncertified_layout`이며 임베딩 불가능의 수학적 증명이 아니다. 별도 일반 비가중 장치 변환 구현을 이 버전에 자동 대입하지 않는다. [S04], [S05]
7. 컴파일 전후에 같은 노드 대응과 엣지 관계, 실제 장치 단위의 `J_ij=C6/r_ij^6`, `Σ_nonedge J_ij < Δ_final < min_edge J_ij`, `Ω_final=0`을 검사한다. 엣지가 없는 그래프는 위 오른쪽 경계를 별도로 처리한다. 이는 **명령된 이상적 최종 Hamiltonian의 충분조건**이며 실제 잡음·유한시간 성공 확률의 보증이 아니다.

원시 표본은 독립집합 검사 → 리터럴 일관성·복호화 → 복호화된 배정의 모든 절·원제약 검사 순서로 평가한다. 선택된 보조 증인이 모든 절을 대표하지 않는 `clause_complete=False`와 실제 배정의 절 위반은 다르다. 증인이 불완전해도 복호화 배정이 모든 제약을 만족하면 유효 추천으로 인정하고 증인 완전성을 별도 기록한다. 보조 노드 수를 추천 수로 세거나 임의 표본 크기에서 Wm을 빼지 않는다. 실패한 복호화도 전체 표본 분모에 남긴다.

| 샷·반복 | 사례당 500샷×5개 배치. 최대 60건 제출·30,000샷, 하드웨어 튜닝 0회, 자동 재제출 0회. 이는 장래 실행 명세이며 이번에 실행하지 않음 |
| 금전 한도 | **현재 승인된 QPU 지출 0원**. 향후 유료 단계는 검증된 요금/예약 상한과 별도 승인된 총액을 동시에 검사. 샷 상한을 금전 상한으로 간주하지 않음 |

컴파일의 0.8 조건은 시간 재조정을 포함하는 별도 실험 설정이다. 같은 논리 문제의 최종 에너지 검사를 다시 통과해야 하며, 무차원 40을 40μs로 해석하지 않는다. 비교 대상마다 준비 비용·물리 펄스 시간이 달라질 수 있으므로 모두 결과에 포함한다. 새로운 하드웨어 튜닝 예산을 얻기 위한 예외로 사용하지 않는다. [S04]

요청 clique 상한과 교차 요청 엣지 지표는 **후보 그래프에만** 적용한다. 보조 그래프는 후보 ID/request_id를 갖지 않는 정점을 포함하므로 별도 입력 경로에서 구조를 검사하고 원모형 제약 연결·lift 인증을 사용한다. 원래 운영 문제의 독립 부분은 후보–제약 관계로 판정한다. 간단한 축약이 작동하지 않는다는 사실만으로 난도를 부여하지 않는다.

### 3.7 비교·후처리·통계

- **운영 기준선:** 원래 이동 유지 x=0, 후보 ID순 실행 가능 탐욕법, b_v 내림차순 실행 가능 탐욕법. 추가할 때 선언 제약을 검사하되 공급 의존성 때문에 탐욕법이 조합을 놓칠 수 있음을 명시한다. 이들의 J와 보행을 고전·QPU 결과와 같은 방식으로 계산한다.
- **주 결과:** 원시 표본의 복호화/선언 모형 유효율, 고정 예산에서의 최대 유효 추천 수, 각 배치 분포, 사건 경로 통과율, BENEFIT의 양수/0/음수 비율, 추가 보행·지연, 준비·풀이·전체 시간과 비용. 최다 추천 수 동률은 정렬된 후보 ID의 사전순으로 고정하고 J로 다시 최적화하지 않는다.
- **후처리 주 분석:** 수선 없음. 보조 분석에서 모든 샘플러에 같은 결정적 수선 적용: 선택 집합 내부 차수가 최대인 정점 제거(ID 동률 처리), 이후 ID순 호환 정점 추가, 복호화와 원모형 검사. 원모형 위반이 남으면 실패. 공급 의존성 때문에 삭제가 운영 위반을 만들 수 있어 '독립집합으로 고쳤다'를 운영 유효로 세지 않는다.
- **무작위 비교:** 동일 실제 그래프의 각 비트를 독립 확률 0.5로 샘플하고 동일 검사/수선·표본 예산을 적용한다. 이는 알고리즘 기준선의 난수이며 합성 요청·합성 그래프를 만드는 일이 아니다.
- q/O/L/U는 모두 **같은 선언 운영 모형의 추천 수**다. 최적값 O를 알면 q/O, O−q, 최적해 적중률. O=0이면 비율 대신 절대값. 모르면 `max(0,L−q) ≤ O−q ≤ U−q`를 보고한다. 체크포인트와 사건 모형의 상하계를 합치지 않는다. 보조 그래프의 높은 독립집합 비율을 높은 추천 품질로 해석하지 않는다.
- 목표값은 평가 전 고정: 알려진 O, 아니면 개발/예비풀이의 유효 incumbent L0. 후자는 '기준해 도달'로 명명한다. 최적성을 증명하는 고전 시간과 QPU 샘플 생성시간을 직접 같은 시간으로 비교하지 않는다.
- 준비/후보 생성/인코딩, 임베딩/컴파일, 큐, 장치 실행·읽기, 검증/복호화/수선, 총 경과시간을 분리 저장한다. 배치 히스토그램만 있으면 실제 첫 성공 시각을 복원하지 않는다.
- TTS99는 보조 지표: IID 가정하 `τ × ceil(log(0.01)/log(1−p))`. 큐·고정 준비비는 별도 더하고 샷 간 상관을 명시한다. 성공 0회는 유한 상한을 제공하지 않으며, 전부 성공해도 p=1로 단정하지 않는다. 배치별 성공률의 95% Wilson 구간 역시 IID 조건부이며, 합친 샷의 상관·장치 드리프트를 보정한다고 주장하지 않는다. [R15]
- τ는 관측된 회당 샘플링 실행·읽기 시간이다. 배치 실행시간만 있으면 배치 시간/반환 샷 수라는 추정임을 표시한다. 백엔드가 이 시간을 제공하지 않으면 성공에 필요한 샷 수와 총 경과시간만 보고하고 장치 TTS를 만들어내지 않는다.
- 비교는 같은 날짜 블록의 paired 차이와 중앙값/IQR, 2,000회 날짜 블록 bootstrap 95% 구간으로 요약한다. 날짜가 10개 미만이면 구간의 일반화 주장 없이 개별 사례·범위로 보고한다. 2,000·95%·10일과 bootstrap 적용은 본 연구 통계 규약(N)이다. 샷 수를 독립 운영 사례 수로 세지 않는다.
- 민감도마다 입력을 재고정하고 고전 난도를 다시 확인한다. 후보 필터, 시간 근사, 운영 모형, 정확 인코딩, 수선의 영향을 분리한다. QPU 주 표본은 주 조건만 사용하며 추가 유료 민감도 실행은 예산에 포함되지 않는다.

## 5. 모델의 정확성과 일관성 검사

| 충돌 가능성 | 이번에 내린 결정·검사 |
|---|---|
| 실제 자료만 사용 vs 대체 후보·보조 노드 | 원자료는 실제, 대체 경로는 의사결정 대안, 보조 노드는 수학 변수로 구분. 실측 요청/자전거를 추가하지 않음 |
| 비가중 목적 vs 수급 개선 | b_v는 자격 조건, 목적은 개수. 집합 BENEFIT 악화를 허용된 결과로 보고하며 목표를 몰래 가중치로 변경하지 않음 |
| 후보 필터 vs 공급 의존 | 단독 불가능으로 제거하지 않음. 개별 편익 필터의 별도 손실은 필터 해제 분석으로 확인 |
| 미래 정보 사용 vs 평가 누출 | 회고적 문제의 입력으로 미래 완료 이동 사용은 명시. 하이퍼파라미터 선택에는 평가 날짜 결과 사용 금지 |
| 관측 시점 통과 vs 시간 경로 위반 | 각각 보고하고 엄격 하위군 정의. 관측 사이 위반이 있으면 전시간 실행 가능이라고 쓰지 않음 |
| 상한·교착 포함 요구 vs 실제 용량 없음 | 확장 제약 정의를 유지하되 현 자료 지표는 NA. 관측 최대치로 합성 상한을 만들지 않음 |
| 고난도 사례 선정 vs 후보 규칙 변경 | 후보·제약 정의를 먼저 고정한 후 새 난도 측정. 기존 37개는 현 설계의 고난도 확인 결과가 아님 |
| 큰 정확 그래프 vs 쉬운 원모형 | 원모형+lifting 기준선 포함. 인코딩 부담과 운영 난도 분리 |
| alpha 항등식 vs 불가능 모형/불완전 표본 | 원모형 실행 가능 증인 선행, 표본은 복호화 검증. 저장 encoded 라벨만으로 증명하지 않음 |
| 장치 수용 vs 같은 문제 비교 | 직접 배치 실패를 보존, 임의 절단 없음. 실제 제약으로 분리 가능한 경우만 독립 문제로 정당화 |
| 물리 충분조건 실패 vs 불가능 주장 | '현재 파이프라인에서 인증 못함'으로 보고. 이상적 충분조건은 필요조건이 아님 |
| 수선 이후 유효율 vs QPU 원시 성능 | 원시 결과 주 분석, 같은 수선은 별도 비용 포함 보조 분석 |
| TTS vs 증명 시간 | 동일한 사전 목표 도달과 증명은 별도. 최적값 미확정은 기준해 도달로 명명 |
| 고전·양자 반복 vs 독립 표본 | 반복은 실행 변동 측정, 통계 블록은 날짜. 히스토그램의 순서 추정 금지 |

설계 의존 순서는 **관측 의미·모형 가정 → 이동 적격 후보 → 고정 S·L·편익 조건 → 선언 제약 → 정확 MIS → 난도 선정 → 장치 검증 → 공통 평가**다. 난도나 QPU 성공 여부를 보고 후보 규칙을 되돌려 조정하는 순환을 주 분석에 넣지 않는다.

## 10. 논문에서 사용할 수 있는 결론의 경계

현재 확인 가능한 결과는 **실측 사례 생성, 후보 충돌 및 일반 재고 제약의 차이, 작은 정확 인코딩, 기존 37개 그래프의 쉬움 인증, 소규모 오프라인 물리 검사**다.

이 설계를 실행한 뒤에는 **조건부 관측시점 모형의 유효 추천 수, 관측 이동 대비 재고 부족 지표 변화, 사건 검증 통과율, 동일 논리 문제에 대한 선택한 고전법과 QPU의 고정 예산 품질·비용·처리 규모**를 주장할 수 있다. 실제 사용자 수락·실패 수요 감소·반납 포화 개선·현장 운영 가능성·모든 고전법 대비 양자 우위·최초성은 해당 추가 증거 없이 주장하지 않는다.

고난도군이 비거나 QPU 적합 입력이 없으면 그 원인과 범위를 결과로 보고한다. 부족한 사례를 만들기 위해 원자료·엣지·용량을 변경하지 않는다. 연구 목표는 유지하고, 현재 장치와 실측 모형의 표현·규모 한계를 결과에 포함한다.

## 11. 문서 검토 기록

- 운영 문헌, MIS·양자 방법, 로컬 코드·산출물을 나누어 읽고 교차 검토했다. 원문 재접근 실패와 이전 확인 범위는 §7에 표시했다.
- 검토에서 발견한 **거리 민감도 반경, 날짜 경계의 5시간 문맥, 원모형/보조 그래프 상하계 단위, 보조 그래프 전용 난도 경로, 불완전 증인과 실제 제약 위반의 차이, 표본 태그와 원모형 기준선 예산**을 본 명세에 반영했다.
- D01–D78의 78개 행이 중복·누락 없이 존재하고, 표의 열 수와 참고문헌 ID 연결을 로컬 문서 검사로 확인했다.
- 이번 작업은 문서 작성과 읽기 전용 검토였다. 분석 코드를 본 설계로 수정·재실험하지 않았고, 계정 인증·노트북·QPU 실행은 하지 않았다.
