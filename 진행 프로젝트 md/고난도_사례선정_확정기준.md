# 고난도 사례 선정 기준 v1.0

결정일: **2026-11-09 / Asia·Seoul**. 상태: **사례 선정 방법 채택**.

사용자가 이미 요청한 문헌 기반 의사결정을 실행한 문서다. 아래 규칙은 추가 선택을 요청하는 초안이 아니다. `레퍼런스.md`의 D13–D25·D53–D59 중 사례 선정에 관한 미정 사항을 이 버전으로 구체화한다. 규칙을 확정했다는 사실과 고난도 사례를 실제로 발견했다는 사실은 구별한다.

## 1. 채택한 방법

**실측 운영창 구성 → 요청 사이 경쟁 구조 측정 → 정확한 축약·쉬운 사례 인증 → 고전 예비실험 → 규모별 난도 분류 → 일반군·고난도군 고정 → 같은 논리 MIS로 고전·QPU 비교**

| 결정 | 이번 연구에서 채택한 규칙 | 문헌 근거와 적용 범위 |
|---|---|---|
| 모집단 | 대여이력·대여소·시간별 수량을 연결할 수 있는 전체 기간. 최다 이용 월은 피크 대조군으로 별도 보존 | 전체 적격 기간이라는 구체 규칙은 연구자 결정. R18·R22의 선정 편향·시간 의존 평가 원칙을 응용 |
| 시간·지역 단위 | 정시 시작, 60분 창, 60분 간격, 출발 대여소의 자치구. 지역·시간창 밖의 관련 배경 이동도 운영 제약에 유지 | R02의 일괄 요청과 R06–R08의 재고 경로 관점을 응용. **60분·자치구는 본 연구 규약** |

| 계산 난도 탐색 대상 | 같은 요청 내부의 충돌과 **서로 다른 요청 사이의 충돌**을 분리. 최대 연결 성분·잔여 문제 크기·요청 간 경쟁을 측정 | R02의 공유 자원 충돌과 R12의 구조별 난도 분석을 응용 |
| 쉬운 사례 처리 | 요청별 clique 상한 도달 또는 정확한 축약으로 풀이가 끝나면 쉬운 대조군. 자료에서 삭제하지 않음 | 상한·축약의 정확성은 아래 수학적 근거. 축약을 활용하는 방법론은 R20 §3.1 |
| 구조 지표 역할 | 구조는 예비실험 우선순위를 정하는 데 사용. 밀도·treewidth·이용량을 합친 임의 난도 점수는 사용하지 않음 | R12 §IV.2, R21 §III.2–3에서 단일 구조 지표의 보편적 난도 판정 한계를 확인 |
| 고전 비교군 | 정확법 HiGHS MILP와 OR-Tools CP-SAT, 구조별 정확 인증. 최종 논문에서는 ReduMIS 등 전문 MIS 방법으로 독립 검증 | 복수 정확법·강한 휴리스틱은 R12·R20·R15에서 가져온 원칙. **구체 소프트웨어 조합은 연구자 결정** |
| 난도 판정 | 아래의 시간·반복·상하계 규약으로 실제 측정. 쉬운 사례들 중 상위 몇 개를 억지로 고난도라고 부르지 않음 | R12의 풀이·증명시간 구별, R15의 비교 범위, R17의 실패 포함 보고를 응용 |

60분 창은 시간별 자료와 맞추는 주 분석 단위다. 분 단위 이동 시각을 쓰더라도 분 단위 재고를 실측했다고 표현하지 않는다. 현재 두 재고 모형을 혼합하지 않으며, 거치대 수를 확인되지 않은 실제 반납 상한으로 바꾸지 않는다.

## 2. 그래프가 큰데도 쉬울 수 있는 구체적인 이유

요청이 1,000개이고 요청마다 대안이 8개이면 후보는 8,000개다. 하지만 요청끼리 자원을 경쟁하지 않는다면 각 요청에서 하나씩 고르면 끝난다. 이 예는 설명용 수학적 예시이며 연구 입력으로 생성한 합성 데이터가 아니다.

요청 r의 후보 집합을 V_r라 하고, 모든 V_r가 clique인지 실제 엣지로 검사한다. 이때 비어 있지 않은 요청 집합의 수를 U_request로 두면:

`독립집합 크기 ≤ U_request`

유효한 독립집합 S가 `|S| = U_request`를 만족하면 **그 자체로 최적성 인증**이다. 요청 사이 엣지가 일부 존재해도 이 상한에 도달하면 같은 결론이다. clique가 아닌 요청 그룹을 요청 수 상한으로 잘못 사용하는 것은 금지한다.

추가로 정점 v의 이웃들이 서로 모두 연결되어 있으면 v를 포함하는 최적해가 존재한다. 따라서 v와 이웃을 제거하고 최적값에 1을 더하는 축약은 정확하다. 최적해에 v가 없다면 이웃 중 최대 하나만 포함할 수 있으므로 그것을 v로 교환해 크기를 유지할 수 있다는 교환 논증이다. 이를 반복한 기록을 저장하고 원래 그래프에서 다시 검증한다.

**축약 후 잔여 그래프가 남는다는 것만으로 고난도는 아니다.** 이번 코드의 기본 축약이 적용되지 않았다는 뜻이며, 전문 풀이기가 더 축약하거나 쉽게 풀 수도 있다. 그래프에 적용한 축약을, 그래프에 담기지 않은 일반 운영 제약까지 보존하는 축약으로 해석하지 않는다.

**5초·60초·5회·상위 10%·1초·20개·3개·70/30 분할·규모 구간은 문헌에서 가져온 정답이 아니라 지금 채택한 연구 규약이다.** 수치에 대한 직접 레퍼런스는 없다. 이를 이유로 결정을 미정으로 돌리지 않고, 버전을 고정하고 변경 시 이유를 기록한다. 이 규약은 기존 37개 결과를 확인한 뒤 정했으므로, 그 결과에 대한 사전등록이라고 표현하지 않는다. 평가 날짜가 확보되지 않으면 기존 날짜를 평가군으로 재사용하지 않고 개발 결과로 보고한다.

비교군에서 얻은 독립집합은 원래 그래프에서 검증한다. `L = 가장 큰 검증된 해 크기`, `U = 유효한 상계 중 최솟값`으로 합치고 `(U-L)/max(1,U)`를 보고한다. 서로 다른 풀이기의 정보로 L=U가 되면 어떤 단독 실행이 시간초과였더라도 더 이상 미해결 사례가 아니다. 제한시간은 정확한 최적 풀이시간이 아니라 관측 종료 시점이다.

‘60초 내 증명 미해결’은 좋은 해를 찾기 어렵다는 뜻과 다르다. QPU가 좋은 해를 빠르게 출력하는 성능과 고전법이 최적성을 증명하는 시간을 같은 지표로 비교하지 않는다. 최종 성능에는 같은 목표 품질의 해 발견시간·성공률을 사용한다. [R12 §II.3·III.1](https://arxiv.org/html/2307.09442v3), [R15](https://arxiv.org/pdf/1401.2910)

## 4. 반드시 구별하는 세 난도

| 문제 | 판정 의미 | 이번 연구에서의 처리 |
|---|---|---|
| 후보 충돌 그래프 MIS | 저장된 노드·엣지에서 가장 많은 후보 선택 | 고전·QPU가 같은 논리 입력을 푸는 비교 단위 |
| 전체 운영 제약 모형 | 요청·재고·시간 등 선언된 모든 제약을 만족하는 선택 | 별도로 풀고 검증. pairwise relaxation의 MIS 결과와 같은 문제라고 하지 않음 |
| 보조 노드를 추가한 정확 MIS | 전체 제약을 정확히 표현하기 위해 커진 그래프 | 원래 운영 모형의 해를 변환한 기준선과 비교. 보조 노드 때문에 느린 현상을 운영 자체의 난도로 주장하지 않음 |

전체 운영 문제의 고난도 사례라고 보고하려면 자료·기준선 검증을 통과하고, 해당 운영 제약을 보존한 입력에서 난도를 확인해야 한다. 일반 제약이 성분 사이를 연결하면 그래프의 연결 성분만으로 운영 문제를 분할하지 않는다. QPU 적합성은 난도와 별도 판정하며, 장치에 맞지 않는 어려운 사례도 모집단·실패 목록에서 제거하지 않는다.

## 5. 이번 코드와 실행 범위

| 파일 | 역할 |

실행 명령(작업공간 안에서):

```powershell
.\.venv-qpu\Scripts\python.exe select_hard_cases.py --summaries outputs/summary.csv outputs/stress/summary.csv outputs/qpu_demo/summary.csv
```

**이번 추가 코드는 구조 탐색·쉬운 사례 인증 단계까지 구현한다.** 60초×5회 복수 풀이기 캠페인, 전 기간 사례 생성, 전문 MIS 재검증을 실행한 것처럼 기록하지 않는다. 기존 `data_process.py`는 피크 사례 생성기로 유지되며, 이번 진단은 명시한 기존 37개 사례에 적용한다. 구조 선별 목록은 ‘고난도 후보’이며 검증 완료된 고난도 사례와 다르다. QPU·인증·노트북은 실행하지 않는다.

## 6. 근거 확인표

| 문헌 | 이번 결정에 사용한 내용 | 그대로 적용하지 않은 내용 |
|---|---|---|
| [R02 Angelopoulos 2016, §II.A–B](https://corelab.ntua.gr/~angelop/Publications/Incentivization_Schemes_One_Way_VSS.pdf) | 요청·차량·주차공간을 공유하는 여행 후보의 충돌 | 예약된 개별 자원과 가중 목표를 서울 집계 재고·비가중 목적과 동일시하지 않음 |
| [R12 Andrist, §II.3·III.1·IV.2–3](https://arxiv.org/html/2307.09442v3) | 복수 알고리즘, 구조별 실제 난도, 해 발견·증명시간 구분 | SA용 hardness parameter를 모든 풀이기의 난도 점수로 사용하지 않음 |
| [R20 Lamm, §3.1–3.2](https://arxiv.org/pdf/1509.00764) | 정확한 축약과 전문 MIS 휴리스틱 | 휴리스틱으로 정점을 고정하는 inexact kernel을 정확한 축약으로 사용하지 않음 |
| [R21 Cazals, 저자 원고 v1 §III.2–3](https://arxiv.org/html/2502.04291v1) | 밀도·treewidth와 난도의 관계가 단조롭지 않음 | 해당 논문의 격자 생성법으로 서울 실측 그래프를 다시 만들지 않음. 최종 발행본 전문을 대조했다는 주장도 하지 않음 |
| [R15 Rønnow](https://arxiv.org/pdf/1401.2910) | 비교 대상·시간·성공확률을 맞춘 양자 성능 평가 | 제한된 비교군 결과를 모든 고전 알고리즘에 대한 우위로 확대하지 않음 |
| [R17 Dolan–Moré](https://arxiv.org/pdf/cs/0102001), [R18 Cawley–Talbot](https://jmlr.org/papers/v11/cawley10a.html) | 실패를 포함한 분포 보고, 선정·평가의 분리 | 서울 자료의 60초·상위 10%라는 수치의 근거라고 하지 않음 |

현재 자료에서 확인되는 구조와 앞으로 더 넓은 모집단에서 찾을 구조를 구별하여 기록한다. ‘문헌에 정확한 임계값이 없다’는 이유로 사용자가 수치를 다시 결정해야 하는 절차는 두지 않는다.
